# 随机刷卡

用户要求刷卡随机，不按固定顺序呈现下一张。本轮仅改变刷卡队列，不改正文、日程、资料来源或专题／文章的编排。

## 行为

- 首页以及筛选后的刷卡流使用Fisher–Yates随机排列。一轮每张只出现一次；上划、下一张、j沿该排列前进，下划、上一张、k沿同一排列回退，不重新抽签。
- 第一张随机；主动深链或已有阅读位置优先恢复，后续卡仍为随机顺序。
- 队列缓存在当前标签页的sessionStorage，刷新或离开到原文／日程后返回不会重排。收藏、标已读、笔记等操作不会洗牌。
- 最后一张点击下一张开始新一轮；滑至末页可点“再随机一轮”。两轮交界避免紧接着重复同一张，单卡集合除外。
- 筛选池独立；不把附录混入默认100张，不影响仅收藏／未读条件。缓存最多8个池，池成员变化会建立新队列。
- 六组专题及四篇官方前瞻的目录、详情内上一篇／下一篇、原文段落仍按论述次序；用户主动选的内容不被随机替换。
- localStorage的lakang:v1数据结构、旧ID、收藏、笔记和导入导出保持；sessionStorage禁用或损坏时降级内存队列，不阻断阅读。

## 验证范围

新增10项队列单元测试与5项浏览器回归；原刷卡测试改用固定随机源检验具体次序，不再误把K001→K002当产品要求。离线冷启动改为检查实际首次随机卡的恢复。原内容校验、原文返回、附录笔记、专题前后篇、布局与离线回归保留。

本地已用Node执行纯算法断言（100卡排列、恢复、深链、轮间去重、空集）；容器无法访问GitHub/npm，完整类型检查、单测、e2e和构建结果以本PR实际远端CI为准。此文件建立时尚未记录远端通过；通过后补PR评论和实施状态。未部署生产服务器。
