# Codex 接手入口

更新：2026-10-26。仓库：Dylan5237/lakang。

## 现在要直接完成什么

基于本库资料，交付一个可运行、可构建、可静态部署的大会会前知识卡网站。主页像刷短视频一样上下切换知识卡，但阅读的是经过编辑的知识，不是视频，不是把原长文塞进一张滚动大卡。

用户已确认的原话意图：
- 结合广州历史交流及专家工作、研究和成果，充分准备本届大会。
- 适合在路上随时翻阅；日程保留；面向所有人，不是私人赠送手册。
- 改成刷知识卡的形式，动车上边刷边获得预备知识。
- 要保证质量和真实性，但不要用“来源真实性”等降格说明占据正文。
- 资料入库，由本地 Codex 接手做成完整网站。

## 阅读顺序

1. `docs/PRODUCT_REQUIREMENTS.md`：范围、交互和离线目标。
2. `docs/EDITORIAL_GUIDE.md`：知识卡写作标准和事实边界。
3. `docs/MATERIALS_INDEX.md`：资料内容与原件状态。
4. `content/agenda.json`、`content/sources.json`、`content/chapters-*.md`、`content/speakers.md`、`content/toolkit.md`。
5. `content/card-examples.json`：卡片编辑标尺，不是完整卡库。
6. `docs/ACCEPTANCE.md`：交付和验证口径。

## 开工方式

先查看现有工作树与分支，不覆盖其他人的变更。用最少必要依赖建立工程；将资料作为内容源，而非硬编码进组件。按一个连贯主线完成：内容卡化 → 卡流与日程 → 本地保存与离线 → 测试与构建。

建议第一版覆盖所有 16 章和 10 位讲者；卡片数量由内容自然决定，通常一章拆为 2—4 个知识单元。不要为凑数写重复卡。示例卡是语气、密度与结构参考，不表示其余正文可自动切段直接发布。

如用户已将完整原件包放到本地，按包内说明导入 `references/originals/`，校验摘要后再提交；不要用空文件、下载说明或伪造路径代替原件。没有原件也不阻塞按仓库正文实现核心网站。

## 最终回报必须包含

提交 SHA；变更文件与内容覆盖数量；实际执行的测试命令及结果；启动、构建、部署命令；离线测试条件；已知未验设备；需要用户提供的真实手机截图位置。只报告做过的验证，不用“应该能”替代实测。

完成首版后，更新 `docs/IMPLEMENTATION_STATUS.md`。视觉验收由用户截图、ChatGPT 审阅；不要把截图和读图分配给本地 Agent。
